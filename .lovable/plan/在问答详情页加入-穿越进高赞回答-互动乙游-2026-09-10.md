# 在问答详情页加入「穿越进高赞回答」互动乙游

## 目标
把当前单篇知乎式回答页，从「只读」升级为「可触发、可穿越、可选择」的互动入口。用户在阅读关键段落时触发穿越事件，进入以该回答为原型的互动乙游世界，通过角色对话和剧情选择推动故事，最终抵达不同结局并回到现实页面。

## 产品形态

### 第一阶段：单篇 MVP（先做这一个回答）
在当前「去责任化」回答里埋一个有趣的「穿越入口」，由用户主动点击触发。点击后页面像被故事吸入一样进入互动世界：
1. 触发：用户点击入口，页面出现失焦、震动和“时空裂缝展开”的响应反馈。
2. 降临：回答页向后退场，用户以第一人称进入外卖员凌晨送餐、楼道冒烟的现场。
3. 对话：通过人物立绘、姓名条、逐字出现的对白和环境旁白推进情节。
4. 抉择：在有限时间或关键节点给出两个带情绪倾向的选择，而非普通表单按钮。
5. 结局：根据选择展示不同剧情、角色反馈和结局称号。
6. 回归：显示「这次穿越，你改变了什么」，并提供「重启世界线」「回到回答」「分享结局」三个出口。

````text
回答页
  │
  ▼
┌─────────────────────┐
│  点击「时空裂缝」入口     │
└─────────────────────┘
  │
  ▼
┌─────────────────────┐
│  穿越转场 + 第一人称降临  │
└─────────────────────┘
  │
  ▼
┌─────────────────────┐
│  角色对话 + 剧情抉择     │
└─────────────────────┘
  │
  ├─ A ──▶ 责任感路线 ──▶ 好结局
  └─ B ──▶ 去责任化路线 ──▶ 坏结局
  │
  ▼
┌─────────────────────┐
│  世界线结局 + 重启/返回  │
└─────────────────────┘
````

### 第二阶段：多回答宇宙（后续扩展）
- 首页/列表页增加「穿越宇宙」入口。
- 每个高赞回答可配置自己的剧情节点（question → scene → choices → endings）。
- 用户可查看自己穿越过的故事线和解锁的结局。

本计划只覆盖第一阶段，第二阶段作为备注不实现。

## 页面改动

### 1. 回答页新增「时空裂缝」入口（用户手动触发）
入口不做成普通宣传卡片，也不自动弹出，而是嵌在回答关键段落处等待用户点击：
- 在「此时会诞生两个选择」段落下方，放置一枚带呼吸光效的圆形“裂缝”入口，旁边显示「检测到可进入的世界线」。
- 入口保持常驻可见、轻微脉动，吸引但绝不打断阅读；不随滚动自动展开。
- 用户点击后，按钮文案从「触碰裂缝」变化为「正在连接世界……」，页面短暂失焦、轻微震动，随后执行全屏穿越转场。
- 底部操作栏可保留一个小型传送门图标作为再次进入的快捷入口，但主入口必须出现在剧情关键段落处。

### 2. 新增互动乙游式「故事世界」
不跳转新页，用当前页内的状态切换实现：
- `mode: 'reading' | 'story'`
- `storyStep: 'intro' | 'choice' | 'ending'`
- `choice: 'A' | 'B' | null`

进入 story 模式后：
- 隐藏顶部导航、问题标题、作者信息、正文、底部操作栏。
- 全屏显示故事场景，采用视觉小说布局：环境画面占满屏幕，人物半身立绘位于中下部，对话框固定在底部安全区。
- 顶部仅保留章节进度、静音和退出按钮，避免破坏沉浸感。
- 对话逐字出现，点击屏幕继续；关键节点收起对话框，再浮出两个剧情选项。
- 选择后人物表情、环境光和对白发生变化，让用户感到角色正在回应自己。

### 3. 故事内容结构

**穿越开场（Intro）**
- 文案：「回答中的字忽然开始脱落。下一秒，凌晨的冷风吹到了你的脸上。」
- 黑场、文字碎片和快速拉近的光效完成从知乎白底到夜间楼道的转场。
- 用户身份明确为“刚送完最后一单的外卖员”，以第二人称叙事。
- 按钮不写常规的「开始」，而写「睁开眼睛」。

**角色与对话（Dialogue）**
- 设置一位引导角色，例如住在楼上的年轻邻居“林夏”，以电话或突然出现的方式与用户建立联系。
- 对话顺序：发现烟雾 → 林夏察觉异样 → 用户判断风险 → 系统提示下一单即将超时 → 进入关键选择。
- 角色不是装饰，她会根据用户的选择改变表情、语气和后续行动。

**关键抉择（Choice）**
- 选项一：「先报警。我不能当作没看见。」
- 选项二：「时间来不及了，这不该由我负责。」
- 每个选项都附一行较弱的内心独白，体现利益与责任的拉扯。

**世界线结局（Ending）**
- 责任路线：你和林夏及时疏散住户，火势被控制；你失去了一单的收入，却获得结局称号「火光之前」。
- 离开路线：新闻里的楼道变成焦黑废墟，林夏发来的最后一条消息停在未读；获得结局称号「无人负责的夜晚」。
- 结局页不直接说教，以角色余韵和一句简短总结承接原回答观点。
- 底部：「重启世界线」「回到高赞回答」「分享我的结局」。

### 4. 互动乙游画风
- **画面**：夜间城市与楼道采用精致二次元半写实插画，冷蓝环境光搭配火情的琥珀橙，避免泛紫的通用科技感。
- **人物**：角色使用半身立绘，至少准备平静、紧张、释然三种表情；人物保持清晰，不用模糊剪影。
- **界面**：半透明深色对话框、细线边框、角色姓名签、章节标记和世界线进度，整体参考视觉小说而非网页卡片。
- **动效**：文字逐字显示、人物淡入与轻微位移、背景慢速景深、选择出现时短暂静止；支持减少动态效果。
- **声音**：第一版保留静音入口和字幕表现，不接入实际音频。

## 状态与数据

本地状态即可，不需要后端：
```ts
type Mode = 'reading' | 'story';
type StoryStep = 'intro' | 'dialogue' | 'choice' | 'ending';
type Choice = 'A' | 'B' | null;

const [mode, setMode] = useState<Mode>('reading');
const [step, setStep] = useState<StoryStep>('intro');
const [choice, setChoice] = useState<Choice>(null);
```

故事内容以场景数组组织，包含背景、说话人、对白、人物表情和下一节点，第一阶段不接后端。

## 实现步骤

1. 在回答关键段落嵌入会发光、轻微脉动的“时空裂缝”入口，仅由用户点击触发。
2. 制作乙游风场景背景和角色多表情立绘，建立统一画风。
3. 实现穿越转场与故事舞台：intro → dialogue → choice → ending。
4. 编排对白、角色表情、A/B 世界线和两个有余韵的结局。
5. 实现逐字对白、点击继续、章节进度、静音占位和退出交互。
6. 验证完整流程、手机 375px 适配、文字可读性、图片加载和减少动态效果。

## 验收标准

- 回答关键段落有一个有趣的“时空裂缝”入口，仅用户手动点击进入，不像普通广告卡片。
- 点击后有完整穿越转场，并进入具有背景、角色立绘和对话框的互动世界。
- 能完成 intro → dialogue → choice → ending 的完整流程。
- A/B 选择分别进入不同结局文案。
- 角色会随分支改变表情与对白，结局有独立称号。
- 结局页有「重启世界线」「回到高赞回答」两个可用按钮。
- 手机 375px 宽度下无遮挡、无溢出。

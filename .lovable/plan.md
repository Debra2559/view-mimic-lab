# 在问答详情页加入「穿越进高赞回答」互动故事

## 目标
把当前单篇知乎式回答页，从「只读」升级为「可读、可穿越、可选择」的互动入口。用户点击「穿越」后，进入以该回答为原型的分支剧情，通过 A/B 选择推动故事，最终看到不同结局并回到页面。

## 产品形态

### 第一阶段：单篇 MVP（先做这一个回答）
在当前「去责任化」回答里埋一个穿越入口。点击后页面进入沉浸式故事模式：
1. 开场：用故事文案把用户拉进场景（外卖员凌晨送餐、楼道冒烟）。
2. 选择：给出 A / B 两个关键决定。
3. 分支：根据选择展示不同后续剧情与结局。
4. 收尾：显示「你收获了什么」总结，并提供「再穿越一次」「返回回答」「分享」三个出口。

````text
回答页
  │
  ▼
┌─────────────────────┐
│  悬浮/底部「穿越」入口   │
└─────────────────────┘
  │
  ▼
┌─────────────────────┐
│  故事开场（场景还原）    │
└─────────────────────┘
  │
  ▼
┌─────────────────────┐
│  选择 A / B          │
└─────────────────────┘
  │
  ├─ A ──▶ 责任感路线 ──▶ 好结局
  └─ B ──▶ 去责任化路线 ──▶ 坏结局
  │
  ▼
┌─────────────────────┐
│  结局页 + 再玩/返回/分享 │
└─────────────────────┘
````

### 第二阶段：多回答宇宙（后续扩展）
- 首页/列表页增加「穿越宇宙」入口。
- 每个高赞回答可配置自己的剧情节点（question → scene → choices → endings）。
- 用户可查看自己穿越过的故事线和解锁的结局。

本计划只覆盖第一阶段，第二阶段作为备注不实现。

## 页面改动

### 1. 回答页新增「穿越」入口
位置二选一，建议同时做并测试：
- 方案 A：正文末尾插入一张故事卡片，标题「穿越进这条回答」，副标题「如果你是那个外卖员，你会怎么选？」，按钮「开始穿越」。
- 方案 B：底部互动栏增加一个「穿越」图标按钮（与赞同/收藏并列）。

最终保留一个主入口即可，另一个作为备选或同时保留。

### 2. 新增「故事模式」全屏覆盖层/路由
不跳转新页，用当前页内的状态切换实现：
- `mode: 'reading' | 'story'`
- `storyStep: 'intro' | 'choice' | 'ending'`
- `choice: 'A' | 'B' | null`

进入 story 模式后：
- 隐藏顶部导航、问题标题、作者信息、正文、底部操作栏。
- 全屏显示故事内容，背景使用深色或氛围色（与知乎白底区分）。
- 顶部保留「关闭 / 返回回答」按钮。

### 3. 故事内容结构

**开场（Intro）**
- 标题：「当你穿越进这条高赞回答」
- 场景文案：复刻回答里的外卖员情境，用第二人称「你」。
- 底部按钮：「我准备好了」

**选择（Choice）**
- 题目：「你刚送完餐下楼，发现楼道里那辆电动车正在冒烟……」
- 两个大按钮：
  - A. 报警 + 通知物业 + 尝试转移
  - B. 这不是我的事，赶紧离开

**结局（Ending）**
- A 路线：火势被控制，你成了邻居口中的英雄，但耽误了订单、被站长批评。总结：责任让社会运行成本降低。
- B 路线：火势蔓延，整栋楼受损，你虽然没受伤，但事后看到新闻感到后怕。总结：去责任化最终让所有人买单。
- 底部：「再穿越一次」「返回回答」「分享我的结局」。

## 状态与数据

本地状态即可，不需要后端：
```ts
type Mode = 'reading' | 'story';
type StoryStep = 'intro' | 'choice' | 'ending';
type Choice = 'A' | 'B' | null;

const [mode, setMode] = useState<Mode>('reading');
const [step, setStep] = useState<StoryStep>('intro');
const [choice, setChoice] = useState<Choice>(null);
```

故事文案写死在前端 JSON 里，第一阶段不配置化。

## 实现步骤

1. 在回答页末尾插入故事入口卡片，文案与按钮样式贴合知乎蓝。
2. 实现 `StoryMode` 组件：intro → choice → ending 三步切换。
3. 增加状态切换逻辑，点击入口进入 story，点击关闭返回 reading。
4. 补齐故事文案（开场、A/B 选项、两个结局、收尾按钮）。
5. 调整样式：故事模式全屏、选择按钮大而易点、结局页突出总结句。
6. 验证：手机宽度下选择按钮不重叠、返回按钮可见、底部固定栏不遮挡。

## 验收标准

- 回答页可见「穿越」入口。
- 点击后进入全屏故事模式，顶部有返回回答按钮。
- 能完成 intro → choice → ending 的完整流程。
- A/B 选择分别进入不同结局文案。
- 结局页有「再穿越一次」「返回回答」两个可用按钮。
- 手机 375px 宽度下无遮挡、无溢出。
